# Discovery and delegated completion contracts

- Host launcher discovery rechecks file identity and permissions before reusing a bounded, brief FX identity scan. Package-dependent Cursor/Pi checks stay fresh; clearing discovery fences late cache publication and never executes an unrelated binary.
- Hermes background completion waits have a deadline. A timeout is unknown completion; never mark delegated rows complete or continue from late manifest results. Retain original read ownership until settlement and retire the captured provider through its existing lifecycle.
- Parent reply completion does not prove delegated work finished. Keep the original execution and child tracking alive until real terminal evidence arrives; follow-up and Stop must still target that execution while the parent is idle.
- The Providers tab mounts a provider's CLI/runtime detail only after it is first selected, then keeps it mounted but hidden so path drafts and pending inspections survive. Do not hide it with `Activity`: effect cleanup would abort pending sign-in and binary inspection.
