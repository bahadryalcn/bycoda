# Stop and wait reasons

- A task's why is structured: `stop` (code, phase, attempt, message, actor, nextAction, at; plus `repair` detail for `repair_exhausted`) and, while queued, `wait` (code, retryAt, waitsOn, message). Schema, codes and helpers: `src/shared/model/host-contracts/task-stop.ts`. `message` and `error` are detail for the owner to read; behavior never branches on them (`bycoda/task-state-from-stop-code`).
- `stop` belongs to a blocked task. It also sits on an active task only while the task waits for the owner's answer (`input_required`), carries a run's time-limit stop until the cancelled turn settles (`budget_exhausted`), or holds an edited task until the owner restarts it (`nextAction: restart`). Storage drops it from any other status; `wait` is kept only while queued, or while a worker idles for its provider usage limit.
- Every Host path that blocks goes through `recovery.block()`, which requires a code. Call sites pass `{ code, message, phase? }`; actor and nextAction default from the code. A blocked row without a code reads "Reason not recorded"; there is no reader for older rows.
- `taskStopSummary` / `taskStopText` (`src/shared/model/taskStopSummary.ts`) are the only title, reason and action for card, list, detail, `taskTransitions`, the daily summary, Host notes, the assistant's tracked-work and chief reads, and the crew detail. `taskStatusLine` maps the summary to board kinds.
- A run's outcome carries `cause` (`owner_stop`, `host_interrupted`, `session_deleted`, `owner_gate`) from `sessionRunState`; the one place provider text is classified is `ownerGateFailure` in `host/sessions/sessionRuns.ts`.
- Waits: `model_quota`, `usage_limit`, `daily_limit`, `crew_capacity`, `dependency` (with `waitsOn`, plus the dependency's stop code once it is blocked), `assistant_hold`. The scheduler writes a wait once per reason and clears it before launch. A dependency the owner stopped stops its waiting task with `dependency_stopped`.
- `task_history` carries `stop_code` and `wait_code`; an update is journaled only when status, a code, title, goal or project changes.
