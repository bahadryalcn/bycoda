# Global voice continuity and result provenance

Use this reference for project navigation, workspace discovery and tool-result verification. Audio protocol, microphone and overlay lifetimes remain owned by the Voice feature.

- `src/app/App.tsx` supplies the same current/remembered project directory used by the rail, filtered through the current lock snapshot. `src/app/workspace/bridges/useVoiceAppBridge.ts` maps persisted local and remote history without opening or submitting a conversation.
- `src/features/voice/model/voiceProjectNames.ts` resolves display/folder aliases into canonical paths. Normalization and partial candidates help discovery only. Partial or ambiguous results require clarification; they never authorize an effect or substitute a guessed path.
- `src/app/workspace/bridges/useVoiceWorkspaceActions.ts` merges stored and loaded metadata, filters before paging and retains loaded/active/archive status. Reads do not select, open, create or submit. Lifecycle actions retain their exact session/project identity, existing owner flows and request deduplication. Orchestrated workers and Inbox-owned conversations retain their separate owners.
- Navigation and selection are not audio settings. The companion must preserve an authorized connection across ordinary project/view/scope changes while binding each accepted utterance to its captured target. A later view or scope cannot broaden an earlier utterance.
- Tool dispatch identity and content provenance answer different questions. A genuine response from the exact captured Host/project/thread/session/request/action can be usable even when desktop/browser contents cannot be attributed to a project. Such content must keep conversational memory/rule provenance unknown; it must not be promoted to trusted owner preferences.
- Desktop approvals can bind either a real coding session or a real assistant thread. Keep those subjects explicit and mutually exclusive through the authenticated relay and native dialog. The thread route is limited to exact desktop-operation approval, not generic native UI or working-copy authority. Preserve app allowlists, snapshot ownership, lock/presence policy, full operation hashes and authority checks before/after approval.
- Unknown effect completion is not success. Preserve original request/operation identity and inspect its receipt instead of automatically repeating an input, launch, send or deletion.

Validate navigation during pending speech, no active coding session, current projects missing from recents, case/diacritic aliases, ambiguous candidates, stored/archived pagination, lock changes after asynchronous reads, and mismatched/out-of-order tool receipts. Report actual installed/provider/native acceptance separately from source and isolated protocol/browser evidence.
