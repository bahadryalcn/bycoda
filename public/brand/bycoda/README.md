# bycoda brand assets

Shell rail marks use `mark-small-black.svg` / `mark-small-white.svg`, generated at a
24px optical size from the canonical geometry with stronger strokes and shorter
drop tips. Regenerate only these transparent vectors with
`node scripts/build/generate-brand.mjs --shell-only`. Full-size marks stay unchanged.

The original mark abstracts a Turkish tea saucer: a six-lobed rim and six petal motifs surround a custom `</>` code seal. The saucer evokes gathering around a shared table; the central seal identifies bycoda as a coding workspace. The favicon retains the scalloped silhouette and code seal while omitting the small petals for legibility. The lowercase wordmark reads `bycoda` without a word space and is drawn as vector paths, so exports do not depend on installed fonts. Do not typeset a replacement beside the symbol.

Palette: graphite `#262930`, silver `#DCE2EA`. Light/dark names refer to the intended background. Transparent PNG exports accompany the fixed-color vectors. For UI with a user-selected theme, choose the fixed-color asset matching that surface, or tint the monochrome adaptive asset with CSS. Leave at least 12 units around the 80-unit symbol; keep the symbol at least 16 px wide and the horizontal logo at least 120 px wide. Preserve aspect ratios and avoid shadows, gradients, or animation within the artwork.

The full dark filenames contain pure black (`#000000`) artwork on transparent backgrounds. No gray, silver, or filled background is included. Use on a light surface; black artwork is invisible on black surfaces. These remain alternative artwork exports, including transparent home-screen sizes for compositing.

The approved mark keeps the six-lobed tea saucer, six separate outlined diamond droplets, and a dominant filled `</>` seal. No lines connect the droplets. Geometry lives in `src/shared/lib/brandGeometry.json`; both the generator and the voice visualizer consume it. Keep clear gaps between the brackets, slash, droplets and rim. The application uses black artwork in light mode and white in dark mode. Desktop app, web installation, and favicon exports use white artwork on black. Red droplet outlines are reserved for startup and optional animation previews.

The marketing website and mobile app are separate repositories. An everywhere update must synchronize their copied assets as well. Keep the website's existing asset URLs and localized social layouts; copy the canonical exports and refresh each social card's brand mark and embedded actual product capture. Visible old marks in product screenshots require a fresh isolated native capture with updated provenance, never a pasted symbol. Mobile runtime, splash and favicon assets must be included in preview staging, alongside its self-contained native icons. Existing ignored Android launcher/splash resources need a targeted refresh before using an already prebuilt native project. Source synchronization does not update installed applications or the published website.

After regeneration, run the website's `node scripts/sync-brand.mjs --source <canonical-brand-directory>` from its checkout. From the mobile checkout, `node scripts/sync-brand-android.mjs` lists existing native resources; `--write` explicitly refreshes only those rasters. Read each repository's local usage guide and preserve its independent Git changes.

Small Windows and favicon rasters are rendered directly at their target size by `scripts/build/brand-icon.mjs`. The16–64px optical variant uses more of the canvas and stronger pixel-sized strokes; its separate drop tips are shortened to keep clear gaps around the rim. Large marks and lockups retain the approved full geometry. Windows ICO entries include16/20/24/32/40/48/64/96/128/256px. The Windows tray selects its actual small-icon metric instead of resizing the large window icon again. Use `node scripts/build/generate-native-brand.mjs --windows-only` and `node scripts/build/generate-brand.mjs --favicons-only` for targeted regeneration. New packaging inputs require a new application build before installed shell icons can reflect them; icon-cache deletion is not part of generation.

The optional tea-red reveal changes the six droplet outlines clockwise from the variant's original ink to tea red `#D32030`. Each transition lasts 0.85 seconds, begins after a 0.5-second hold, and is offset by 0.12 seconds. All droplets reach red at 1.95 seconds and hold. The saucer outline, code seal, and wordmark retain their original ink; backgrounds stay transparent. Reduced motion shows the final red outlines without animation. Startup uses `mark-tea-red-loading.svg`: exactly one red outline advances clockwise every 240 ms in a 1.44-second loop. Reduced motion keeps all six outlines white. The SVGs animate natively even as image sources; no runtime animation library is required.

Regenerate SVG/PNG exports with `node scripts/build/generate-brand.mjs` (requires the project's Playwright Chromium). Then run `node scripts/build/generate-native-brand.mjs` for desktop, Android/iOS, installer and Expo input formats; add `--sync-mobile` to copy the two Expo inputs into the separate mobile checkout. Run `node scripts/build/generate-social-brand.mjs` to refresh only the emblem in the existing `x-header-v1.png`, preserving its campaign layout. This generates source assets only; it does not build, install or publish an application. The ICO favicon uses the 16/32/48 PNG exports. Keep the existing outlined wordmark unchanged when updating the symbol.
